# Builder spec traceability

Audit of the approved [builder-spec.md](builder-spec.md), §§2–9 and every E1–E22.
Code/test links name the implementing symbol and the covering test. “Covered” means
an automated regression exercises the rule, not proof of all possible inputs.
GAP marks incomplete implementation or missing direct coverage even when nearby
tests pass. The #22 approval is recorded in the spec before implementation.

Closed audit gaps: required per-kind edit fields and strict boolean coverage; task/part
checkpoint subjects and proposal-only commits even with unrelated staged paths; deleted
context and 150-result boundary coverage; watcher tasks and safe failure reasons.
The routing replay also exposed timestamp-based compile caches reusing same-size
source within one second; compile checks now emit checked-hash bytecode.

Historical measurements/estimates in §6 are distinguished from executable rules.
§9's historical “Today” new-issue workaround is superseded by the specified rerun.
Safety replay 9 deliberately ends FAILED without a PR, as required by its own safety
rule; the other acceptance replays reach DONE with persisted draft PR records.
Live acceptance (§11) is outside this mock-only session and has not been claimed.

## Remaining GAPs

- **G1 — Size units:** `_file_excerpts` uses Python character counts, not UTF-8 byte counts. Non-ASCII files can exceed the nominal KB budgets. ASCII boundary/budget coverage exists; multi-byte boundaries lack a test.
- **G2 — Exhausted context budget:** outlines are truncated to each file's allowance; sufficiently large outlines/lines can consume the allowance before start/end sections. No regression proves “every def/class” and “always start/end” under those competing limits. The spec needs a deterministic budget precedence for impossible-to-fit outlines.
- **G4 — Read contract:** read tools impose additional source-extension/directory/symlink exclusions beyond §4.2, a 3,000-file/512KB discovery inventory, 16,000-character response truncation and per-call inspection budgets. They cannot read/search every otherwise safe repo path verbatim. Keep existing context protections until the read contract and budgets are reconciled.
- **G5 — Crash atomicity:** validation and ordinary I/O failures are atomic, but process death during multi-file disk writes is not. Temporal redelivery restores the checkpoint (covered by the killed-worker replay); standalone Factory.status/advance does not itself reset dirty source and has no transaction journal. A crash between Git commit and durable task metadata also needs a focused fault-injection test.
- **G6 — Cost ceiling:** max_job_attempts is enforced, but the stated dollar ceiling is an estimate, not a metered spending cap. Read-tool input tokens, provider pricing changes and repeated infrastructure recovery are not bounded by an actual dollar budget; historical measurements were not rerun here.
- **G8 — Credential detector limits:** environment credentials shorter than eight characters are excluded; literal SDK keys not present in the environment are not comprehensively recognized. Existing tests cover long environment values and provider-token patterns, not those boundary cases.
- **G7 — Every flag environment:** the gate checks/turns off policy-configured environments and production, rather than discovering all project environments. No test covers an extra environment absent from policy. Offline mode also deliberately permits disclosed, unverified drafts, so the unconditional live flag rule only holds in live mode with all environments configured.
